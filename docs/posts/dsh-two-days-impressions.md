过去两天，我把日常开发搬到了 DeepSeek Harness（下称 DSH）上——一个跑在本地、用浏览器操作的 AI 编码代理。我是写 Minecraft 插件的（AsDuels、DsBorder），AI 方面的开销主要在两处：opencode 的 Go 订阅按用量走，DeepSeek 按余额走。所以上手第一天我就装了两款插件：`dsh-opencode-usage` 盯用量和余额，`dsh-sound-alerts` 给任务加上提示音。这篇就记录一下这两天的真实感受和这两款插件的用法。

## 它和聊天工具有本质区别

DSH 不是又一个对话框。它是一个跑在我电脑上的执行环境：文件、终端命令、后台任务都归它管，一个多步骤的活儿它能跨很多轮自己干完。浏览器页面只是入口，真正的读写都发生在本地文件系统里，所以它产生的每处改动都是能 review 的 git diff，而不是对话里随手贴的一段代码。

## 几个和预想不太一样的地方

Windows 沙箱是一道真实的约束。只读状态下跑 PowerShell 是受限语言模式，.NET、COM、反射这些全被挡住，只有拿到写权限才放开。刚开始觉得麻烦，后来反而觉得安全——命令必须一次写对。

审批策略我是分阶段放的。第一天用 `ask` 模式，每一步都要确认；观察它改文件没出过岔子之后，第二天就改成了 `never`，改为事后翻转录记录来审查。信任建立起来后，`never` 带来的效率提升非常明显。

长任务真的能跑完。配合目标、任务清单和后台任务，它能把一个复杂的活儿拆开、一轮一轮地啃，中途不需要人守着。需要并行的时候，还能把独立任务委派给子代理，或用 workflow 分阶段铺开，计划和执行分得很清楚。

## dsh-opencode-usage：用量与余额监控

选它是因为两笔开销的"死法"不一样：opencode Go 套餐是用量，静默消耗；DeepSeek 是余额，静默流失——都是等部署失败才发现钱没了的那种。这个插件把两者都放进了侧边栏：

- 底部常驻一个徽标，显示首个已配置 provider 的用量或余额，异常时自动变红；点开是详情卡片，各 provider 的用量/余额、重置倒计时、历史趋势、告警和 Key 配置都在里面。
- 数据源目前有两类：opencode-go 的用量（5h 滚动/周/月，来自官方用量接口）和 DeepSeek 的余额（官方余额接口）。Key 的解析顺序是环境变量优先（`OPENCODE_API_KEY` / `DEEPSEEK_API_KEY`），面板手填只作兜底，明文存在 `~/.dsh/dsh-opencode-usage.json`，权限 0600。
- 最有价值的是突增告警：用量历史会写到本地，单次增幅超过 5%、深夜还在涨、5h 额度烧到 80% 都会提醒，余额低于阈值也一样。对 Key 可能泄露的人来说，这比"余额归零才发现"靠谱太多——异常消耗能被第一时间抓住。
- 采样间隔 5 分钟，历史只在插件运行期间记录；颜色、字号、阈值、卡片外观都能调，告警要不要影响徽标颜色也可以分类型开关。

总的来说，把成本可见性直接嵌在工作流里，比另开一个页面看报表实用得多。扣分项是明文兜底配置和偏粗的采样粒度，留到下面说。

## dsh-sound-alerts：任务的声音反馈

长任务要能放心挂后台，得先有可靠的通知。这个插件把 DSH 的各种事件映射成不同的提示音，通过 SSE 推到浏览器播放（失败会回退到轮询），播放时不阻塞对话：

- 权限请求就绪是双音提醒，助手提问是三连上行音，命令或工具报错是下行警示音，任务正常完成则是上扬的完成音。
- 支持全局静音，也能按类别单独关；`sound_alert_status` 还能查静音状态和各类触发次数。

把审批改成 `never` 之后，我听到最多的是完成音。任务在后台跑的时候我可以去干别的事，靠声音就能分辨"还在跑"和"需要处理"，这是长任务工作流里最缺的一环。

## 遇到的问题

`dsh-opencode-usage` 偶尔会返回非法输出（`value is not lossless JSON`），看起来是插件自身序列化层的 bug，值得去提个 issue。功能本身可用，但这种偶发错误会动摇可靠性预期。

另外，workflow、子代理的 API 边界和沙箱规则几乎没有正式文档，全靠试错摸索；5 分钟的采样粒度也让徽标和真实数值有分钟级滞后，对余额型数据可以接受，对用量型数据略显粗糙。

## 小结

两天不算长，但方向已经很明确：DSH 把"跟 AI 对话"变成了"在真实仓库里跟 AI 协作"，插件机制则是它最亮眼的扩展点——上面这两款插件分别解决了成本感知和异步任务感知的问题，而且都不需要离开主工作流。会继续用下去，下一步是把那个序列化 bug 的 issue 提了。
